Repo worktree: /Users/joyfort/MyProjects/Tufu-rpg (branch feature/rpg-mode; step 1 is commit db67574). CB = Recovery/StudyProject/Assets/Scripts/Assembly-CSharp/CodeBase. Read Docs/RpgMode/Design.md sections 4.3, 7, 8.1, 9, 13 and 19, and Docs/RpgMode/Step1Brief.md ("Hard constraints") first.

## Goal
With the RPG toggle on, killing enemies gives the party XP and gold instead of permanent stats. The party shares one level (cap 60). Every level multiplies every hero's Health, Damage and Defence by 1.08 and fully heals the living heroes. Spawners respawn forever on a short fixed cooldown with no daily charges. Enemies get a level from their spawner's place in the island and scale with it. Quest stat rewards become XP. The HUD shows level, XP bar and gold, and the UI of closed systems is hidden.

With the toggle off, the original game and pet mode must behave exactly as today.

## Hard constraints (same as step 1, plus save rules)
1. Every hunk in a pre-existing file is one of:
   - (a) a pure insertion guarded by `RpgModeConfig.Enabled` (an early `return`, a wrapped block, or `cond && !RpgModeConfig.Enabled` / `RpgModeConfig.Enabled || cond` added to an existing condition);
   - (c) a substitution by an `RpgControl`-style helper that returns exactly the old expression when RPG is off.
   Do not reformat or rewrite other original lines. Methods marked "Native ELF VA" or "Original ELF" keep their bodies byte-identical apart from gated insertions.
2. **Save layout with RPG off must not change.** Add `RpgUd` as the LAST child of `GameUserData`, constructed only when `RpgModeConfig.Enabled` (so `Child("rpg", ...)` is never called when off). Never add fields to existing Ud classes (some are positional). Never use `DataVar`/PlayerPrefs for RPG state.
3. Never re-point `PlayerModel.Unit`, never move or add `PlayerTag`, no new ECS tags.
4. A new `ModifierSource` is not needed: use `RpgHero` (23) for base, role and level modifiers. Modifiers with the same Name+Source+ModifierType merge (PercentMultiplicative values multiply, StatBase.cs:66-89), so each kind needs its own Name: `rpg.hero` (role ratios, existing), `rpg.base` (base correction), `rpg.level` (level growth). Update a modifier by removing the old one by Name, then adding the new one. `UpdateValue` is protected; never mutate a modifier's Value in place.
5. Writing `CurrentHealth` on a dead pet desyncs `UnitCore.IsDead` from `PetState` (UnitDamageSystem.cs:132-136). Only heal heroes whose `HeroModel.IsAlive` is true and, for Pudge, `!IsReviving`.
6. A code-built TMP label with Chinese text must go through `PetStatsText.SetText` / `ApplyCjkFont`, or it renders as boxes. Any new HUD is parented under `joystick.transform.parent` (HudContainer), never under the Joystick (it has its own full-screen canvas and drag handler). Set `raycastTarget = false` on graphics that should not block the joystick.

## Numbers (all in RpgModeConfig so they can be tuned without code)
- Team level cap 60. `xp(L) = 20 × 1.1^(L−1)`; `need(L) = (1.5 + 0.3L) × xp(L)` to go from L to L+1. At cap, XP is set to 0 and further XP is discarded.
- Level-difference factor on XP, by `teamLevel − enemyLevel`: ≤0 → 1.0, 1 → 0.9, 2 → 0.75, 3 → 0.55, 4 → 0.35, 5 → 0.15, ≥6 → 0.
- `gold(L) = 5 × 1.1^(L−1)`. Gold is not affected by the level difference. Round at grant time: `max(1, round(gold))`.
- Spawner kinds, checked in this order (new static `RpgSpawnerRules`):
  1. boss: `config.Gates != null && config.Gates.Count > 0` → cooldown 600 s, XP ×20, gold ×20;
  2. elite: `config.IsEliteBoss` → 180 s, ×5, ×5;
  3. static: `config.IsStatic && !config.DisableAfterFirstClear` → 120 s, XP 0, gold ×0.5;
  4. normal: everything else, including item and VIP spawners → 45 s, ×1, ×1.
  One-time spawners (`DisableAfterFirstClear`) keep their one-time behaviour. A cooldown must never be 0 (0 hits the instant-refill branch at EnemySpawner.cs:~792-806).
- Enemy level from `config.LocationNumber` (island i) and `config.RelativeOptimumTime` (rel): `L = clamp(round(Ls(i) + rel × (Le(i) − Ls(i))), 1, 60)`, island windows 1 → 1..5, 2 → 5..10, then Ls(i) = Le(i−1), Le(i) = round(10 + (i − 2) × 50 / 15) so island 17 ends at 60 (keep the window table in config as two int lists, generated by that rule). Clamp: when rel > 1, `L = min(L, Le(i) + 1)`; bosses (kind 1) get `Le(i) + 1`.
- Enemy scaling: after the original stats are set, multiply enemy max Health and Damage by `1.08^(L−1) × EnemyHealthScale` and `× EnemyDamageScale` (both default 1), then set current health to the new max. This is a rough stand-in until the baked table of design 9.3 exists.
- Hero base (design 4.3): level-1 Pudge = Health 120, Damage 10, UniversalDefenceFlat 2. Player Config gives Health 100, Damage 0 (+10 PlayerBaseAttack in pet mode), Defence 0, so every hero gets `rpg.base` Flat modifiers Health +20 and UniversalDefenceFlat +2 (put the two numbers in config as BaseHealthBonus 20, BaseDefenceBonus 2).
- Role ratios (design 4.3), defence becomes a ratio: add `DefenceRatio` (default 1) to HeroDefinition and use PercentMultiplicative for it. Update the defaults and the asset: protagonist 1/1/1; golem Health 1.6, Attack 0.6, Defence 1.5; cultist 0.8, 0.7, 0.8. Set golem `DefenceFlat` to 0 (keep the field for compatibility).
- Level growth: `rpg.level` PercentMultiplicative `1.08^(L−1)` on Health, Damage, UniversalDefenceFlat (no modifier at level 1). HealthRegen does not scale.
- Quest XP: a quest step with stat rewards gives `5 × xp(Le(step.LocationNumber))`; a quest chain reward with stat rewards gives `20 × xp(Le(island))`, island = the LocationNumber of the chain's last step. Quest XP ignores the level difference.
